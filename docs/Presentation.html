Collaborative Code Editor
Yjs CRDT Engine

Yjs (Conflict-free Replicated Data Type) ensures that edits from multiple users merge correctly without data loss or conflicts, even under network latency.

  • Server holds in-memory Yjs documents per room
  • Client requests full state via yjs-sync-request
  • Incremental updates via yjs-update events
  • Binary state persisted to MongoDB every 5 seconds
Multi-file Support
  • Create, rename, and delete files per room
  • Active file tab synchronized across all users
  • Each file tracked with unique ID and revision number
  • File list persisted in roomCodeState in-memory Map
Sync Events

Additional Features
  • Syntax highlighting via PrismJS
  • Revision counter prevents stale state conflicts
  • Initial sync sent only once per socket-room pair

Real-time Presence and Cursor Awareness
Presence System

Implemented in services/presence.js as an in-memory Map. Tracks active users per room.

  • addUser — registers socket in room on join
  • removeUser — cleans up on leave or disconnect
  • getUsers — returns active socket list per room
User Events
EventPurpose
users-in-roomBroadcast user list update
user-joinedNotify others of new user
user-leftNotify others of departure
Cursor Awareness

Cursor positions and user metadata broadcast in real time using Yjs awareness protocol over Socket.IO.

EventDirectionPurpose
awareness-updateBidirectionalBroadcast cursor + user data
awareness-removeBidirectionalRemove user cursor on leave
Disconnect Handling
  • Detects all rooms the socket was in
  • Removes user from presence Map
  • Broadcasts users-in-room update to all
  • Sends user-left and awareness-remove events
  • Cleans up initial sync markers

Challenges and Solutions
Yjs State Persistence

Yjs operates in-memory — persisting binary state across server restarts was non-trivial.

Implemented a dirty-room Set and a 5-second persistence timer that saves changed Yjs documents as binary Buffer to MongoDB.

Socket.IO Authentication

Securing WebSocket connections to prevent unauthorized room access.

Socket.IO middleware verifies JWT from handshake auth object before any event is processed.

Multi-user Code Conflicts

Simultaneous edits caused race conditions with simple event-based syncing.

Adopted Yjs CRDT ensuring conflict-free merging of concurrent edits without data loss.

Initial State Delivery

New users joining mid-session needed full current state, not just future updates.

Implemented sync-request / sync event pairs for both Yjs (yjs-sync-request / yjs-sync) and code state to deliver full state on join.
